系统总览

无人车能力分布在 Hub 后端（调度、新石器云 API、行程状态机）、Web 运营端（订单、行李看板、车队、大屏）、设备集群（Neolix 准入与遥测）、小程序（下单 / 行李 MatchAndBook）。本页用模拟数据复现核心链路，便于对外讲解。

两条业务线（同一套车队，不同状态机）

代取 / 外卖（courier）

  • 表：delivery_orders + delivery_dispatches
  • 后台 Worker：待调度认领 → 选车 → Neolix 发任务 → 回调 / MissionSync 推进
  • Web：配送订单 Tab、手动派车、轨迹

开学行李（luggage）

  • 表：delivery_luggage_orders + delivery_luggage_trips
  • 下单：MatchAndBook（拼单 / 新车 / 排队）→ 订单挂 trip_no → 行程挂 vin
  • Worker：ProcessQueue、ProcessDepartures、SyncTrips(GPS)
  • Web：行李看板、固定线路、提前发车、车辆治理 V2

订单如何关联到车

行李单 不存 VIN，通过 trip_no 关联 delivery_luggage_trips.vin。排队单 trip_no 为空，待 ProcessQueue 匹配后写入。

order_no→ trip_no→ VIN / vehicle_code→ Neolix 任务 / GPS

车队管理

名册在 delivery_fleet_bindings。Neolix 车审进配送项目时自动 upsert；也可 Web 手工维护。实时电量/GPS 来自新石器云快照（拉取，非车端直连 Hub）。

车牌/代号VIN园区启用电量上电在线判定故障

相关 API（Hub）

GET /api/delivery/fleet · POST /api/delivery/fleet/status · POST /api/delivery/fleet/:vin/power

行李调度逻辑

小程序 MatchAndBook 与后台队列共用同一优先级。调度循环只扫描 business_type=delivery 且有车队绑定的项目。

MatchAndBook 三级匹配

P1 同路线候车行程→ P2 空闲车新建行程→ P3 入队 queued

行程 / 订单状态机

行程 (trip)

boarding→ delivering→ arrived→ returning→ closed

到达后订单转待取件，车辆可立即返程；GPS 进半径判到达/回场。

订单 (order)

queued→ boarding→ delivering→ awaiting_pickup→ completed

模拟行程与订单

订单号trip_noVIN起→终订单状态行程状态

调度模式

  • dynamic：同园区车队内选空闲车
  • fixed_route（江阴）：必须存在启用线路 OD，且 VIN 限定在线路绑定车辆内

代取 / 外卖调度

与行李分离：使用 delivery_orders 状态与 delivery_dispatches 执行投影。DispatchWorker 周期认领 dispatching 订单并调用 Neolix 发任务。

created→ dispatching→ waiting_vehicle→ enroute→ arrived_dropoff→ completed
订单号取件站送达站状态VIN任务 ID

设备集群 & 遥测

Neolix 车在设备页显示在线 = vehicleAvailable==1 || powerState（云快照）。EdgeLink :8083 管边端设备连接，不等于无人车 GPS 流。

来源数据刷新方式
新石器 Cloud电量、GPS、上电、故障、任务HTTP 拉取 batchGetVehicleList；token+签名
项目凭证project_neolix_credentials按 X-Project-Id 隔离
任务回调missionStatus（非 GPS 流）StartMission 时 backUrl
行李 SyncTrips到达/回场Worker 用 BatchStatus 取 GPS

车辆治理 V2

影子状态、统一控制面、命令账本与事件流；与行李调度「外控/离线摘除」开关联动。Web：VehicleGovernancePanel。
